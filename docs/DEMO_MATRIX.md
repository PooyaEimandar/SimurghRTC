# SimurghRTC Demo Matrix

This inventory covers all 18 entries in the [Janus demo catalog](https://janus.conf.meetecho.com/demos/) reviewed on 17 October 2026. All adaptations are **Planned**. These are Unreal sample use cases with original implementation and assets, not a copy of the Janus website.

Shared demos use one client API and the same native Unreal application logic. They select Direct Unreal or Janus through configuration. Janus extensions require `SIMURGHRTC_WITH_JANUS=1` and the corresponding runtime capability. An operation can use shared track/data primitives while its service setup remains Janus-specific.

Android and iOS ARM64 Unreal clients are included in the planned client coverage, using [separately built libwebrtc](MOBILE_CLIENTS.md). Each demo's evidence must name the desktop/mobile target, device/OS, codec set and build profile. No desktop or simulator result establishes physical-device support.

## Android and iOS acceptance

All mobile outcomes are currently **Unverified**. Record an individual Passed/Failed/Unverified/Unsupported outcome and reason for each of the 18 entries on each platform. An unsupported path is a documented coverage gap, not evidence that the requested feature has been completed. Admin/Monitor remains operator/development functionality and is intentionally excluded from ordinary mobile player packages.

| Demo group | Mobile acceptance requirements |
|---|---|
| Echo Test, Video Call, Text Room | Physical Android/iOS clients exercise the common C++/Blueprint controls against Direct Unreal and applicable Janus services. Verify text/binary capabilities, two-way media, cancellation, reconnect and app lifecycle through [SR-107](../ROADMAP.md#e04-unreal-server-and-client-integration), [SR-208](../ROADMAP.md#e06-media-lifecycle-and-unreal-playback) and [SR-305](../ROADMAP.md#e08-provider-conformance-and-optional-janus-builds). |
| Device Selection, Canvas Capture | Verify permissions, camera switching/orientation, audio route changes and packaged UE render-target capture on each mobile renderer/device. Generated frames do not establish camera or render-target support. |
| Streaming, Video Room, Video Room multistream, Audio Room, Recorder/Playout | Validate negotiated codecs, concurrent decode/encode limits, audio routing, thermal behavior and the relevant service lifecycle on physical devices. Measure participant/track limits independently of desktop results. |
| Screen Sharing | Provide platform-specific capture/consent integration and any required app extension or foreground-service setup. Test OS-ended capture and resume; a successful camera call does not establish screen-sharing support. |
| SIP Gateway, NoSIP SDP/RTP | Use the same controlled external fixtures and typed Janus extensions; verify mobile codec negotiation, audio interruptions and cleanup. |
| End-to-end Encryption, Multichannel Opus, Web Audio Processing, Virtual Background | Prove hooks, formats, processing costs and dependencies in the selected mobile libwebrtc build. Record target gaps explicitly; reduced-codec builds cannot silently claim the full demo set. |
| Admin/Monitor | Keep privileged operator code/assets out of Shipping mobile clients; common client diagnostics remain available. |

Package the shared mobile samples under [SR-405](../ROADMAP.md#e10-sample-packaging-and-developer-workflows). Use the [app size procedure](MOBILE_CLIENTS.md#app-size-validation) under [SR-807](../ROADMAP.md#e18-build-validation-and-diagnosability) to report core RTC overhead separately from demo assets and optional effect/model downloads. [SR-903](../ROADMAP.md#e20-release-qualification-and-packaging) collects the per-platform demo and size evidence for release.
